# RFC 0009: WiFi

- **Status:** Draft. Implemented and QEMU-verified end to end against a
  real WPA2 access point; see "Verification".
- **Labels:** `rfc`
- **Author:** platform readiness work (`docs/PLATFORM-ROADMAP.md` §19)
- **Requires:** RFC per `CONTRIBUTING.md` — this adds a new init
  subsystem, a second secret store, a kernel config change, and three
  upstream dependencies.

---

## Motivation & Problem Statement

RFC 0008 made Novi installable on real hardware. A laptop with no
Ethernet port then installs perfectly and cannot reach the package
repository — which is the delivery mechanism for the desktop and for
everything else past the base image (RFC 0007). WiFi is what makes the
rest of the system reachable on the machines people actually own.

## Proposed Design

### wpa_supplicant, with internal crypto

Built with `CONFIG_TLS=internal` and libtommath, so it links **no
OpenSSL**. The base image deliberately has none — `novi-verify` exists
precisely so that stays true (RFC 0006) — and adding a TLS stack in
order to get onto a network would undo that in a single step.

**iwd was the alternative and is rejected.** Its control interface is
D-Bus, so it would drag a message bus daemon into a base image whose
whole point is that it does not have one.

`libnl` comes with it (nl80211 is how userspace talks to mac80211), and
`iw` for diagnostics: when WiFi does not work the first question is
always "does the kernel see a radio, and what does it think it can do",
and nothing else on this system could answer it.

### No WPA3, and this is a stated limitation

SAE and OWE need elliptic-curve crypto — `crypto_ec_*` and the bignum
operations `dragonfly.c` calls — and `CONFIG_TLS=internal` does not
implement EC. Turning them on links cleanly right up to
`undefined reference to crypto_ec_get_prime`, which is where this was
found.

Three ways out: link OpenSSL (undoes the reason the whole stage
exists), link **mbedTLS** (small, self-contained, has EC, supported by
wpa_supplicant 2.11 — the real answer, and its own piece of work), or
ship WPA2 only.

WPA2-Personal and WPA2-Enterprise cover essentially every network in
service, and WPA3 routers run transition mode, so this connects to
those too. **It will not connect to a WPA3-only network.** Said out
loud here rather than left for someone to discover in a cafe.

### Credentials are not declared state

```
network.wifi           = on | off      # the supplicant
network.wifi.interface = auto | wlan0
```

and nothing else. A WiFi passphrase is a secret, and
`/etc/novi/system.conf` is world-readable and a file this project
actively encourages committing to git. RFC 0005 settled the rule —
**configuration is declared; secrets are not** — and this is its second
application, after `/etc/shadow`.

So: `system.conf` declares *that* this machine uses WiFi;
`/etc/novi/wifi.conf` at 0600 holds *which* networks and their keys.
`novi-state diff` can tell you the supplicant should be running; it
cannot tell anyone your passphrase.

The store is **wpa_supplicant's own configuration format**, not
something Novi invented and translates. One file, one parser, already
understood by every piece of WiFi documentation on Linux — and if
`novi-wifi` is ever inadequate, `vi` still works.

`novi-wifi add` stores the derived 256-bit PSK rather than the
passphrase. That is not real protection — the PSK is equivalent for
joining the network — but it stops a passphrase someone reuses
elsewhere from sitting in a file in plaintext.

There is deliberately no `services.wifi` key: the network domain owns
that service, exactly as it owns `network.dhcp`.

### Wired first, wireless second

`udhcpc` runs on one interface, and a laptop has two, so something has
to choose. Wired wins: it works without credentials, and on a machine
with a cable plugged in it is what the person plugging it in meant.
`network.interface = wlan0` overrides.

A wireless device is identified by `/sys/class/net/*/phy80211` existing
— the kernel saying what the device *is* — not by a name starting with
`wl`. Naming is a convention.

Per-interface DHCP (a lease on every link that has one) is the right
long-term answer and a bigger change than this service.

### Firmware

Most WiFi chips need firmware blobs this image does not ship. `ath9k`
needs none; `iwlwifi`, `ath10k`/`ath11k`, `brcmfmac`, `mt7921` and
`rtw88` all do. So on a large fraction of real laptops the driver will
load and the radio will not come up until a firmware package exists.
That is a packaging and licensing question, not a code one, and it is
listed rather than glossed.

## Alternatives Considered

**iwd.** Smaller than wpa_supplicant and uses the kernel's crypto, but
its interface is D-Bus. Rejected above.

**Put the PSK in `system.conf` and mark it "sensitive".** NixOS allows
this and warns about it. A project whose pitch is "commit your
machine's configuration to git" cannot rely on a warning; the design
has to not offer the footgun.

**Invent a Novi WiFi config format.** A second format to parse, a
translation layer to get wrong, and no benefit over the one every
existing document already describes.

## Implementation status

- `build/25-wifi.sh` — libnl, wpa_supplicant, `iw`; installs
  `novi-wifi`; builds hostapd **for testing only**, never into the image
- `packages/novi-wifi` — `list` / `add` / `forget` / `scan` / `status`
- `init/services/wifi/` — the supervised supplicant, with
  `notification-fd`
- `packages/novi-state` — `network.wifi`, `network.wifi.interface`
- `init/services/network/run` — wired-first interface selection
- `kernel/config-x86_64` — `CONFIG_MAC80211_HWSIM=m`

### Three bugs, two of them mine

- **A passphrase length check that rejected every passphrase between 10
  and 99 characters.** It was written as
  `case "${#pass1}" in ?|??|???|…)`. `${#pass1}` is the length
  *rendered as a string*, so a 13-character passphrase is `"13"`, which
  the two-`?` pattern matches. Found by feeding it a 13-character
  passphrase. It is an arithmetic test now.
- **`wpa_supplicant -s` was not a valid option in the build.** The run
  script passes `-s` to log through syslog, and the comment next to it
  said so — but `CONFIG_DEBUG_SYSLOG=y` was not in the build config, so
  wpa_supplicant printed its usage message and exited. s6 restarted it,
  and `s6-rc -a list` reported the service **up** the whole time,
  because for a longrun that means "wanted up", not "running". So
  `novi-state diff` reported the machine converged while nothing had
  ever associated. The same trap this project has now hit three times
  (RFC 0004's `syslog`, and twice here).
- **`sit0`**, fixed in the same area during RFC 0007 and worth
  restating: "the first interface that is not `lo`" picks the
  IPv6-in-IPv4 tunnel pseudo-device a `CONFIG_IPV6_SIT` kernel creates
  at boot.

## Verification

QEMU has no WiFi hardware of any kind, so verification runs **two
`mac80211_hwsim` radios** talking over the kernel's own virtual medium:
one running `hostapd` as a WPA2 access point with `udhcpd` behind it,
one running Novi's `wifi` service as a station. The handshake between
them is real.

hostapd is built from the same upstream tree but is **not installed
into the image** — it is delivered to the test VM on a separate disk. A
test dependency in the shipped image would be a worse bargain than an
untested feature. (It needs `CONFIG_TLS=internal` too: its default
crypto backend is OpenSSL and it does not ask.)

The machine had **no wired NIC at all** for this run, so WiFi is
demonstrably what connected it.

- `novi-wifi add NOVI_TESTNET` accepted a 13-character passphrase,
  wrote `/etc/novi/wifi.conf` at mode `0600`, and
  `grep -c novitest12345` on that file returns **0** — the passphrase
  itself is not stored, only the derived PSK.
- `novi-state set network.wifi on` → `diff` showed the drift → `apply`
  wrote a generation and started the service;
  `s6-svstat` → `up (pid 934) … ready`.
- `novi-wifi status` → `ssid=NOVI_TESTNET`, `key_mgmt=WPA2-PSK`,
  `pairwise_cipher=CCMP`, **`wpa_state=COMPLETED`**.
- `iw dev wlan0 link` → `Connected to 02:00:00:00:01:00`, with bytes
  moving in both directions.
- **A DHCP lease over WiFi**: `inet 192.168.50.20/24 scope global
  wlan0` and `default via 192.168.50.1 dev wlan0`.
- `ping` through the access point: 2/2.
- `novi-state diff` clean afterwards.

## Roadmap

- **WPA3**, via mbedTLS as the crypto backend.
- **Firmware packages**, so the drivers that need blobs can have them.
- **Per-interface DHCP**, instead of one interface chosen by rule.
- **A network applet in `novi-panel`.** `novi-wifi scan` is the whole
  interface today, and the desktop's status bar icons were generated
  and left unwired precisely for want of real WiFi data.
- **`novi-state diff` should notice a crash-looping longrun.**
  `s6-rc -a list` reports "wanted up"; `s6-svstat` knows whether it is
  actually running. Using the weaker signal is a flaw in a state engine
  whose premise is observing reality, and it is what hid the `-s` bug
  above. It is not done here because the obvious implementation
  reintroduces a boot race RFC 0004 fixed — a service still starting
  would read as crashed, convergence would call it drift, and every
  boot would burn a generation. It needs its own design.
